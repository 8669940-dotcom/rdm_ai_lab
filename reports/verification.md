## 실행 서버와 브라우저

- Streamlit 1.67.0의 공식 localhost agent API로 9개 경우를 실행했다. 상태 모두 ready, 예외 없음. `app_runtime_check.json` 참조.
- 처음 Edge 전면 활성화가 실패했으나 사용자가 앱을 전면에 연 뒤 Windows 접근성 상태와 실제 스크린샷으로 확인했다.
- 재점검 계획의 기본 지표 20대/81대/22대/2대를 대조했다. 유형별 감시드론 이름 클릭으로 전체20대, 정비 구분별 사후정비 이름 클릭으로 전체18대 상세를 확인했다. 돌아가기에서 선정20대와 요약이 복원됐다.
- 모델 검증의 하반기 AP0.7877·ROC-AUC0.8814·월20대 적중38건·무작위평균13.8건이 계산 파일과 일치했다. 데이터·과정 화면의 세 파일 건수도 일치했다.
- 실제 표시에서 검증 기간 물결표가 취소선으로 표시되는 문제를 발견·수정하고 다시 확인했다. 표 머리글과 지표를 읽을 수 있었고 페이지 오류는 없었다.
- 사용자 앱 주소: `http://127.0.0.1:8503`. 상태 점검 응답은 `ok`, 검증 API는 `disabled`로 확인했다. 이 작업에서 띄운 임시8766 검증 서버만 프로세스와 포트를 대조한 후 종료했다.

AppTest 시작 시 bare-mode ScriptRunContext 경고가 출력되지만 실제 서버에서는 새 경고·트레이스백이 없었다. 자동 검사와 브라우저 확인은 실제 정비 효과나 새로운 기종/부대 일반화를 증명하지 않는다. 2025년 시험 성능은 정답 부재로 검증하지 않았다.

Windows 줄바꿈 검토도 수행했다. CSV 바이트를 보존하면서 CRLF를 정상 줄끝으로 인정하고, 생성 JSON/Markdown은 LF를 고정했다. 마지막 재실행에서도 AP0.7877·선정20대·위험22대가 유지됐고 전체 검사 및 타입 검사가 통과했다. Git에 실제 저장될 바이트와 기록된 해시가 일치해 체크아웃의 줄바꿈 정규화로 생길 불일치를 확인·해소했다.
