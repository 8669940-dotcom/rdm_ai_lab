# 분석 준비 이후의 절차와 문제 해결

필요한 절만 읽는다. 확정 규칙은 프로젝트 `AGENTS.md`, 업무 조건은 `README.txt`, 설정값은 `analysis_config.json`이 소유한다.

## 1. 현재 관측과 처리 기준

`reports/data_profile.json`에 원본별 행·열·해시, 월별 건수, 결측, 정비 구분별 고장 공란, 수치 분위수와 시계열 일관성 점검이 있다. `.md`는 사람용 요약이다.

| 관측/후보 | 초기 방침 | 후속 확인 |
| --- | --- | --- |
| 예방정비의 고장 코드·고장 유형 공란 | 행 유지, 해당 없음 범주 후보 | 사후·긴급정비 공란이 있는지, 생성 규칙 |
| 첫 관측 정비의 직전 정비 경과일 공란 | 이력 없음 표시, 0일과 구분 | 최초 관측 이전 정비 존재 가능성 |
| IQR 밖의 수리시간·비용 등 | 삭제하지 않고 정비 구분·심각도별 확인 | 단위 오류인지 심한 고장인지, 처리 전후 검증 |
| 월 가동률 | 기본 피처 제외 | 정비 직후 가용성, 이번 달 열 부재 |
| 드론 ID | 이력 결합·최신 행·제출키에 사용 | 모델 입력의 ID 암기 가능성 |
| 부대 코드·고장 코드 | 후보/제외 근거 비교 | 저빈도 범주, 고장 유형과 중복, 부대 일반화 |

프로필은 관측 증거다. 결측 발생 원인, 최적 전처리 또는 인과관계가 자동 확정된 것은 아니다. 품질 판단에 따라 처리하면 원본·처리 후 수와 대상 키를 기록한다.

## 2. 이력 피처와 분할

- 파일 역할·원본 행 번호를 메타데이터로 보관하고, 드론·정비일을 기준으로 정렬한다. 출력 시 시험 원본 행과 다시 결합한다.
- 현재 정비의 입력 속성은 정비 직후 확정된 값인지 확인한다. 과거 집계는 `history_date < maintenance_date`를 만족하게 한다.
- 예: 이전 90일 사후/긴급정비 건수, 마지막 관측 고장 이후 경과일, 이전 예방정비 당시 누적시간 대비 현재 누적시간 증가량. '이전 정비 중 고장'과 숨겨진 `failure_within_30days` 정답은 다르다.
- 2025·2026의 피처를 파일별로 처음부터 초기화하지 않는다. 앞 기간 기록과 연결하되 각 행의 이후 기록은 제외한다. 이력 없는 상태는 0건과 구분한다.
- 초기 검증 시작 제안은 2024-07-01이다. 30일 정답 성숙을 고려하여 `training_date + 30일 < validation_start`를 만족하는 행만 학습시키는 보수적 방안을 기록한다. 2024-06 전체를 제외하는 달 단위 방식도 가능하다. 선정한 방식·행 수를 저장한다.
- 검증 구간 전체를 한 번에 예측하는 고정 모델인지, 월별 재학습인지 명시한다. 전처리·모델·하이퍼파라미터·임계값을 같은 검증 구간에 반복 최적화한 낙관성도 한계로 적는다.
- 시험 정답은 강사가 보유한다. 미래 정비를 관찰해 숨겨진 정답을 재구성하거나 가짜 0으로 채우지 않는다.

## 3. 비교와 지표

- 기준선: 같은 월·같은 최신 드론 후보에서 무작위 20대(고정 시드·반복 평균과 분산), 경과연수 순 20대. 모델은 로지스틱 회귀 등 단순 기준 모델부터 비선형 후보와 비교한다.
- 주 지표: AP 또는 정의를 명시한 PR-AUC와 월별 20대 적중. `average_precision_score`를 쓰면 AP임을 명시하며 사다리꼴 PR-AUC와 같은 숫자라고 가정하지 않는다. 불균형의 크기는 실제 양성률로 확인한다.
- 보조 지표: ROC-AUC, 재현율, 정밀도, 월별 편차, 확률 보정 정도, 운영 비용. 양성·음성이 모두 없는 구간에서는 계산 불가능한 지표를 `null/계산 불가`로 표시한다.
- 한 드론이 같은 달 여러 정비 행을 가질 수 있다. 정비 기록별 채점과 최신 드론별 운영을 구분해 산출하고 명칭을 붙인다. 강사에게 월 20대 채점 단위가 확인되기 전 동일하다고 단정하지 않는다.
- 모델 선정표에는 검증 기간, 전처리, 비교 설정, 지표, 비용, 계산시간과 해석상의 장단점을 남긴다. 특정 모델이 모든 면에서 우수하다고 미리 적지 않는다.

## 4. 임계값·정원·설명

- 검증 확률에서 가능한 판정 변경점과 모두 표시/아무것도 표시하지 않는 정책까지 비용을 비교한다. 후보 탐색 간격, `>=` 비교, 동률 비용 처리 기준을 기록한다.
- 기본·민감도 비용을 각각 계산한다: `FN*300 + flagged*60`, `FN*600 + flagged*60` (만원). `threshold_cost`로 개별 후보 비용을 계산할 수 있다. 임계값을 시험 기간 성능으로 고르지 않는다.
- 이 식의 flagged는 위험 표시 건수다. 정원 20대 제한이 없으므로 상위 20대만 점검하는 실제 운영 비용과 별도 표로 제시한다. 드론 단위로 적용하는 경우 분모·최신 정비 기준을 적는다.
- 최종 후보는 이번 달 최신 정비 81대다. 검증 완료 모델 확률을 원본 106행 순서와 맞춘 뒤 `rank_latest`를 호출한다. 20대 선정은 위험 기준과 독립적이다.
- 지역적 기여도 도구를 적용할 때 모델 종류와 설명 척도(확률/로그오즈 등)를 확인한다. 전체 피처 중요도와 개별 드론의 상위 요인을 혼용하지 않는다. 설명할 근거가 없으면 관측 특성과 추가 점검 권고를 분리해 쓴다.

후속 단계의 권장 위치이며 현재 존재하는 결과로 간주하지 않는다.

| 임계값 | 300/600만원 비용표·선정 근거 | 검증 데이터 사용·정원 분리 |

## 6. 문제 해결과 토큰 절약

| 증상 | 확인·해결 |
| --- | --- |
| `python` 명령 없음 | `py -3 --version` 또는 설치된 Python 실행 파일을 확인한다. 실행 파일 경로를 명시하고 명령을 기록한다. 전역 환경 변경은 피한다. |
| 실행 위치에 따라 파일을 못 찾음 | 도구는 `__file__` 기준 루트를 사용한다. 프로젝트 루트에서 문서의 명령을 실행한다. |
| 한글 깨짐 | 콘솔은 `python -X utf8 ...`, CSV는 `utf-8-sig`로 읽는다. 원본을 다시 저장하지 않는다. |
| `ModuleNotFoundError` | 준비 스크립트는 외부 패키지가 필요 없다. 후속 모델 환경은 `python -m pip`가 같은 인터프리터인지 확인하고 필요한 패키지만 설치한다. |
| `KeyError: availability_rate`/정답 | 파일별 실제 스키마를 확인한다. 이번 달 가동률과 시험/이번 달 정답의 부재는 제공 조건이다. 가짜 열을 모델 입력/평가에 채우지 않는다. |
| 해시 불일치 | 원본이 편집·인코딩 변경되었는지 비교한다. 기준 해시를 덮지 말고 변경을 복구하거나 데이터 버전 변경을 명시한다. |
| 저장된 프로필이 오래됨 | 원본 해시를 먼저 확인한 뒤 `python scripts/profile_data.py`, `python scripts/check.py`를 순서대로 실행한다. |
| 확률 수·순위가 어긋남 | 행 수·키·정렬 전 source_index를 대조한다. 확률을 정렬된 다른 행에 위치로 붙이지 않는다. |
| 원인 불명 오류 반복 | 전체 학습을 재실행하기 전에 최초 실패 명령·오류·최소 재현 입력을 기록하고 해당 계산만 고친다. |
| 대화에 CSV/로그가 과다 출력됨 | 요약 모드나 필요한 컬럼/기간 집계만 출력한다. 상세는 파일로 저장하고 변경된 함수·오류 주변만 읽는다. |

### 함수 단독 사용

프로젝트 루트에서 임시 명령을 계속 재작성하기보다 후속 학습/평가 스크립트가 다음 함수를 import하게 한다. `scripts/` 안의 스크립트에서는 `from rdm_common import ...`로 불러온다.

```python
from rdm_common import rank_latest, threshold_cost

# rows와 prob는 동일한 원본 행 순서여야 한다.
selected = rank_latest(rows, prob, capacity=config["capacity"])
cost_300 = threshold_cost(y_valid, p_valid, threshold, miss_cost=300)
cost_600 = threshold_cost(y_valid, p_valid, threshold, miss_cost=600)
```
